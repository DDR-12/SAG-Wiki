## Model responsibilities

Location: **Settings → Model settings**.

| Configuration | Purpose | Required for |
| --- | --- | --- |
| Answer model (LLM) | Write answers, call tools and summarize search results | Q&A and enabled search summaries |
| Decision model | Judge whether candidate passages provide necessary evidence | SAG2 deep search and CLI semantic search |

Local indexing and quick search need neither model. A decision model alone enables semantic retrieval. An answer model alone cannot perform SAG2 retrieval that depends on a decision model.

## Configure each field

### Provider

Selecting a provider fills its endpoint. Answer providers include OpenAI, Anthropic, Google Gemini, DeepSeek, Alibaba DashScope, Zhipu, Moonshot, SiliconFlow, OpenRouter, Ollama, 302.AI and a custom OpenAI-compatible endpoint. Decision model providers include Zleap, 302.AI, OpenRouter, Typesafe and Custom. New installations default to Zleap; existing endpoint and model settings are preserved. The judging API is not a chat API, so those chat providers are not offered as decision models.

Answer generation and decision models use different APIs. Endpoints are not interchangeable simply because they share a provider. A custom service must support the relevant API. Anthropic's official API lists models and tests the connection; chat and tool calls still use OpenAI Chat Completions. To chat with Claude, choose OpenRouter or point a custom endpoint at a compatible gateway. Gemini's default address is the official OpenAI-compatible endpoint, while model listing and connection tests use Gemini's own API. Ollama reads models from `/api/tags` and chats through the same server's `/v1` compatible API. A local Ollama server usually needs no key.

### Endpoint

Enter the API base URL provided by the service, not its web chat address. Presets fill this automatically. For a proxy or self-hosted service, check its path and protocol.

When switching to a different service origin, supply that provider's API key. The app does not automatically reuse the previous provider's key with the new origin.

The decision model accepts a base URL such as `http://127.0.0.1:8000/v1`, or a complete `/systemone` or `/decisions` endpoint. The endpoint suffix is not added twice.

For answer models, Chat Completions remains the default. To use Responses, enter the full endpoint, such as `https://api.openai.com/v1/responses`, or the corresponding proxy URL. This enables streamed answers, function calls and reasoning state replay. Reasoning strength uses `reasoning.effort`; the highest UI level maps to `max`. GPT-6 Astra and GPT-6.1 Sol do not offer a reasoning-off level. Available levels depend on the model and service; choose a supported level or restore the default if rejected. A base URL ending in `/v1` continues to use Chat Completions.

### Decision model authentication

- **API Key**: use for services that require a key. Existing configurations retain this default.
- **No authentication**: use for local decision model services that do not require a key. No authorization header is sent, and saving removes the previously stored decision model key.

The service must implement the decision model API. For the CLI, use `sag config --url http://127.0.0.1:8000/v1 --model YOUR_MODEL --auth none`. Switch back to a keyed service with `--auth bearer --key-stdin`.

### Available models and model name

After an API key and base URL are filled in, the app loads that provider's models: OpenAI-compatible services use `GET /models`, Anthropic uses `GET /v1/models`, Gemini uses `GET /v1beta/models`, and Ollama uses `GET /api/tags`. A successful list fills the **Model** menu. If loading fails, the menu falls back to built-in presets, and **Enter model IDs manually, one per line** stays available. Enter one exact model ID per line, without commas. Duplicates are removed on save. Connection testing uses the selected model.

For the decision model, enter one model ID in **Model name**. New installations use `Zev-1` on the Zleap Open Platform; switching to Zleap also automatically fills in `Zev-1`. The base URL is `https://api.zleap.com/v1`, requesting `/v1/systemone` with API key authentication. See the [decision model documentation](https://platform.zleap.com/docs/decision). When switching to another provider, check that the model name is supported.

### API key

With Zleap selected, **Get API Key** opens the [Open Platform console](https://platform.zleap.com/console). Create a key there and enter it in the decision model card. Configure Zleap decision and 302.AI answer model keys separately.

Enter the key for the selected service. The field stays masked and cannot be revealed in the interface. A saved key is shown as `Saved · ••••••••`; leaving it blank preserves the key. **Remove saved key** deletes that key immediately. Keys are written only to `credentials.json` in the local app data directory. They are not stored in settings JSON, logs or error text.

When both providers are 302.AI, entering a key can fill the other unconfigured field automatically. Review both configurations before saving.

### Test connection

Use **Test connection** on each card to verify the endpoint, model and key. Then select **Save settings**. Tests may send validation requests and incur provider charges.
The answer-model test asks for a short reply; output length follows the model service's defaults.

## Setup sequence

1. Configure the decision model, test it, save and run a deep search.
2. Configure and test an answer model that supports tool calling.
3. Save, select that model in Q&A and ask a question with verifiable sources.
4. Adjust prompts, reasoning or tool permissions under [Q&A settings](/en/docs/chat#qa-settings-in-detail).

## Connection problems

- Authentication failure: check the provider, key and expiry.
- Unknown model: verify the exact ID and account access.
- Invalid endpoint: check the API URL and required path.
- Timeout: check the network and service. Answer and context-summary calls share Request timeout in Q&A settings. Summary body timeouts have bounded retries; if they still fail, try 300 seconds. Increasing the client deadline may not help if the model service or proxy disconnects earlier. See [Q&A and context management](./chat).
- No tool calls: verify that the model and API support tools, then check that model's bindings.

Keys are stored in the current user's application data directory. macOS uses owner-only file permissions; other processes running as that user may still read them. Do not publicly share the data directory. See [Data and privacy](/en/docs/privacy).

## MinerU document parsing

Open **Settings → Model settings → Document parsing · MinerU**. Choose **302.AI** or **MinerU official**. Saving the matching key/token makes MinerU the preferred parser; clearing it restores local parsing.

302.AI uses the enterprise knowledge base's MinerU 2.x contract: Base URL `https://api.302ai.cn`, upload at `/302/upload-file`, create with `POST /302/v2/mineru/task`, and poll with `GET /302/v2/mineru/task?task_id=…`. Authentication is `Authorization: Bearer <API Key>`; enter only the key, without the Bearer prefix.

302 parses PDFs only. Defaults are version **2.5**, **Automatic** parsing, a 60-second request timeout, a 2-second polling interval and a 30-minute task deadline. Advanced settings offer versions **2.0 / 2.5** and **Automatic / Text / OCR**. Time limits are client-side controls. Other formats use the applicable built-in parser or installed Docling; components are not installed automatically.

![MinerU provider, key and connection test](/images/product-mineru-en.png)

**Test connection** checks only the selected parser endpoint. It accesses no account API logs, uploads no files and creates no task. A 400 / 422 response for missing task parameters establishes reachability only, not parsing permission; 401 / 403 means the request was rejected. Results appear beside the button. Validate actual parsing with a small PDF.

302 responses support task identifiers, result URLs, direct Markdown and JSON-encoded strings. Split PDF results must preserve page mappings before publication; otherwise parsing falls back locally without truncating content. Both previous 302 choices migrate to this single configuration and retain the saved key.

Split parts are merged from their structured results with the original page markers kept. Repeated headers, footers and page numbers are dropped; code blocks become fenced code with their language, caption and footnote; charts keep their description and footnote; other named types keep their text as paragraphs. A type with nothing readable fails the conversion with its name and page number, then falls back to local parsing.

MinerU official continues to use `https://mineru.net/api/v4` and its official token, with separate VLM / Pipeline options. Keys are never reused across providers and providers are not switched automatically. Remote parsing sends the original document; see [Data and privacy](/en/docs/privacy).

## Advanced runtime settings

Model settings also provides retry count, backoff intervals and a total request deadline. HTTP 499 counts as a retry; the deadline covers requests, delays and reading responses. See [Runtime settings](/en/docs/preferences#runtime-settings) for the other groups.
